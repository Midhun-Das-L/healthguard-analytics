# healthguard-analytics

**HealthGuard: Healthcare Provider Fraud & Readmission Dashboard**

A working Django application built from the business idea in `notebooks/fraud_detection.ipynb`:
**find Medicare providers whose claims look fraudulent**, so investigators can focus on the riskiest
providers first. A second module from the original prototype scores **30-day readmission risk**
for diabetic inpatients, so care teams can prioritise follow-up calls.

## Quick start

```bash
git clone https://github.com/Midhun-Das-L/healthguard-analytics.git
cd healthguard-analytics
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python manage.py setup_demo          # migrate, train both models, load scores, create login
python manage.py runserver
```

Open http://127.0.0.1:8000 and sign in as **admin / admin12345** (change it: `python manage.py changepassword admin`).
`setup_demo --username you --password ...` sets your own login instead.

Run the test suite with `python manage.py test home`.

## What's in the app

| Page | What it does |
|---|---|
| **Dashboard** | KPIs (providers flagged, reimbursement at risk, unreviewed cases), fraud-probability histogram, risk levels, claims-vs-reimbursement scatter (click a dot to open a provider), investigation pipeline, top-risk providers, feature importance, plus readmission KPIs. A **batch selector** and **live threshold slider** recalculate everything through `/api/dashboard/`. |
| **Provider risk list** | Filter by risk, review status, minimum probability or provider ID. Sort, paginate and export to CSV. |
| **Provider detail** | Why the provider scored high (key features vs. the median honest provider), all 31 features, and an **investigation workflow** (status + notes, saved with reviewer and time). |
| **Score new claims** | Upload Beneficiary / Inpatient / Outpatient CSVs (Kaggle format), plus an optional known-outcomes file. The notebook's feature pipeline runs, every provider is scored and saved as a new batch. Demo files for 150 unseen providers can be downloaded from this page. |
| **Readmission risk** | Searchable encounter worklist with risk levels, follow-up toggles, charts, and per-encounter risk factors. You can also upload a CSV and download its scores. |
| **Model performance** | Model comparison (Logistic Regression vs. Random Forest vs. SVC), ROC curves, confusion matrix, readmission drivers. |
| **Admin** (`/admin`) | Raw access to batches, provider scores and encounters. |

## About the data (please read)

* **Fraud:** the notebook used the Kaggle *Healthcare Provider Fraud Detection Analysis* files
  (`Train_Beneficiarydata-1542865627584.csv`, `Train_Inpatientdata-…`, `Train_Outpatientdata-…`, `Train-…`).
  Those raw files were **not in the repository**, so `data/fraud/sample/` contains a **synthetic dataset with
  the exact same columns** (600 providers, ~30k claims), generated by `home/ml/sample_data.py`. Model numbers
  shown in the app are computed on that sample. To use the real data, download it from Kaggle and run:

  ```bash
  python manage.py train_models --fraud-dir /path/to/kaggle/folder --only fraud
  ```

  Then upload the real files on **Score new claims** (the full outpatient file is about 100 MB, so allow a minute).
* **Readmission:** uses your real `model_data.csv` (6,773 prepared diabetic encounters). The data is only
  weakly predictive (hold-out ROC-AUC ≈ 0.59), but the High-risk group is readmitted about 3× as often as Low
  (18% vs 6.5%). It's useful for ranking who to call first, not for clinical decisions.

## Fixes compared with the prototype

* Hard-coded absolute CSV paths (`/home/bobyf/...`, `C:\Users\USER\...`) made the app crash on any other machine. Paths now come from settings.
* The model was trained at import time on every server start. It's now trained once and loaded from `ml_models/`.
* The forms posted nothing useful (duplicate field names, placeholder "Company (Ex. Google)" fields) and the views ignored the input. Uploads are now validated, scored and stored.
* The notebook fitted `StandardScaler` separately on the validation set, matched labels by row order instead of by Provider, and predicted on a hand-typed row. It now uses a proper Pipeline, joins labels by Provider id, and uses stratified hold-out evaluation with class balancing.
* Dropped the `django-admin-soft-dashboard` dependency. Its template tags and images weren't in the repo, which broke the layout.

## Configuration

Copy `env.sample` to `.env`. Settings include `DEBUG`, `SECRET_KEY`, `ALLOWED_HOSTS`, `FRAUD_FLAG_THRESHOLD`
(default 0.5) and optional PostgreSQL/MySQL `DB_*` variables. For production: `DEBUG=False`, a real `SECRET_KEY`,
`python manage.py collectstatic`, and `gunicorn --config gunicorn-cfg.py core.wsgi` (a `Dockerfile` and Render `build.sh` are included).
